# 日志排查

开梯子后某个网站打不开、怀疑分流不对、或者定期体检时，按这里做。核心思路：**三端各看一段**。

| 端 | 能看出什么 | 看不出什么 |
|---|---|---|
| Mac · Clash Party | 每个连接是直连还是代理、命中哪条规则、哪个程序发起的 | 到 VPS 后走住宅还是 VPS |
| iPhone · 小火箭 | 每个连接是直连还是代理、命中哪条规则 | 是哪个 App（只有部分请求带 App 标识） |
| VPS · Xray | 走代理的流量最终从**住宅**还是 **VPS** 出口出去 | 直连的流量（根本不经过 VPS） |

---

## 1. 导出客户端日志

- **Clash Party**：内核日志在 `~/Library/Application Support/mihomo-party/logs/`（`core-日期.log`）。排查前可以把日志级别临时调到 `debug`，查完调回。
- **小火箭**：导出连接记录和 DNS 记录（`proxy-*.db`、`dns-*.db`）。
- 记下**出问题的大概时间**和**哪台设备**，方便定位。注意 Mac 的时区设置，日志时间按系统时区记录。

## 2. 脱敏（交给 Codex 等本地 AI 处理）

把下面整段发给本地的 Codex，先改好方括号里的内容：

```text
任务：对我导出的代理软件日志做隐私处理，处理后的文件要发给别人分析"规则是否正常、有无异常"。

输入：文件夹 【日志文件夹路径】 里的所有日志（Clash Party/Mihomo 的 core-*.log；小火箭的 proxy-*.db、dns-*.db，请转成 CSV）。
输出：在旁边新建 sanitized/ 文件夹，原始文件一律不改。

一、保留：时间、协议、目标域名、目标端口、命中的规则、策略/节点、进程名或客户端标识；所有 warning/error/超时/DNS 失败；网卡变化、TUN 启停、规则/订阅更新事件。域名原样保留，但去掉网址路径和 ? 后的参数。

二、必须处理：
1. IP（IPv4/IPv6）用 HMAC-SHA256 + 运行时随机密钥（只在内存，不落盘不打印）替换成 IP4-前8位 / IP6-前8位，同一 IP 替换结果一致；后面加类别：[私网] [手机热点]172.20.10.0/28 [公网] [VPS] [住宅IP]。198.18.0.0/15（假IP）和 127.0.0.0/8、::1 原样保留。
   我的 VPS IP：【填】；住宅 IP：【填】；VPS 域名：【填】——这些出现时替换成 [VPS]/[住宅IP]/[VPS域名]，不要原样留下。
2. 替换成 [已删除]：订阅链接、token/key/password/uuid/sid/session 字段、UUID、邮箱、手机号、MAC 地址、电脑名、用户名、/Users/xxx/ 里的用户名、Wi-Fi 名称、Cookie、Authorization。
3. 删除本机源端口。

三、去掉无关内容：连续完全相同的行只留一条并标注"(重复 N 次)"；UI、托盘、更新检查等与网络无关的日志。

四、生成 sanitized/summary.csv：按"域名+命中规则+策略"分组，列：域名,命中规则,策略,次数,首次时间,末次时间,报错次数。

五、自检：扫描 sanitized/ 确认没有残留的 IP（假IP/本机除外）、UUID、邮箱、手机号、MAC、订阅链接、我填的 VPS IP/住宅 IP/VPS 域名；报告每个文件处理前后行数和自检结果；运行完删掉脚本，不保留密钥。
```

## 3. VPS 分流检查

1. 3x-ui 面板 → **Xray 设置 → 日志 → 访问日志**填 `/var/log/x-ui/access.log`，保存，**重启 Xray**。
2. 手机、电脑正常用一会儿 X、Reddit、Claude、ChatGPT、Google。
3. SSH 登录 VPS 运行（最后的数字是统计最近几小时）：
   ```bash
   bash <(curl -Ls https://raw.githubusercontent.com/SilasReedWest/vps-template/main/deploy/route-check.sh) 1
   ```
   输出只有「平台 | 出口 | 次数」，不含你的 IP 和用户名，可以直接发给别人看。
4. **查完关掉**：访问日志改回 `none`，保存并重启 Xray，然后 `rm -f /var/log/x-ui/access.log`。

推荐的常驻日志设置：日志级别 `warning`、访问日志 `none`、错误日志留空、隐藏地址 `full`、DNS 日志关。

**预期结果**：

| 平台 | 应走出口 |
|---|---|
| ChatGPT、Claude、X/Grok、Reddit | `residential-us`（住宅） |
| Google/YouTube、Meta（FB/IG/WhatsApp）、Discord | `direct`（VPS） |

## 4. 常见现象对照

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 国内小程序/App 开梯子打不开，关了能开 | 某个后台域名不在国内名单，落到兜底走了美国 | 在日志里找命中 `FINAL`/`Match` 的国内域名，加进「追加：直连的域名」 |
| 开梯子、关梯子都打不开 | 对方服务器问题（维护） | 等一会儿再试 |
| 日志里大量 `interface not found`、`network is unreachable` | 换网络 / 断网的那几分钟 | 正常；长时间不恢复就把 TUN 关了再开 |
| 日志里出现 `using GLOBAL` | 误切到了全局模式 | 切回「规则」模式 |
| 某个 AI 连接是 `DIRECT` | 规则漏了 | 立刻报告，加进代理规则 |

**原则**：国内服务和金融支付直连；第三方通用的反欺诈 / 客服 / 统计服务（ThreatMetrix、LivePerson、AppDynamics、Tealium、Optimizely 等）**保持走代理**，保证开梯子时海外银行、支付、电商看到的都是美国 IP；加密货币交易所走代理。某个国内金融 App 因此出问题时，临时关梯子用。
